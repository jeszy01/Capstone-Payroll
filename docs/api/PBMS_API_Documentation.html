1. Overview

PBMS (Payroll & Benefits) is an Express 5 and PostgreSQL service in backend-render/. The React app calls it, and the HR2, Finance and ESS systems connect to it server to server.

ItemValue
Base URLhttps://<pbms-render-host> (the frontend reads it from VITE_API_BASE). Paths have no version prefix.
FormatJSON (Content-Type: application/json), UTF-8, unless an endpoint says otherwise.
Request sizeJSON bodies up to 5 MB. Funding receipts are raw file bodies up to 5 MB.
DatesYYYY-MM-DD. Timestamps are ISO 8601 in UTC. "Today" for claims and HMO rules means Philippine time (Asia/Manila).
MoneyPhilippine pesos as numbers, rounded to 2 decimals.
CORShttp://localhost:5173 and the origins listed in ALLOWED_ORIGINS.
List sizeMost lists that read through the shared row helper (users, compensation, HMO, loans) stop at 1,000 rows and have no paging. GET /hmo/history has paging; GET /audit-logs returns the latest 2,000 logged entries plus older browser-recorded activity.

Response format

A successful response wraps its result in data. A failed response has error with a stable code and a readable message. 204 No Content has no body. Exceptions: GET /health and GET /api/health have no wrapper, and funding receipts return the file itself.

// Success
{ "data": { "id": "c386ed75-..." } }

// Failure
{ "error": { "code": "VALIDATION_ERROR", "message": "employee_no is required." } }

2. Authentication

App users: bearer token

POST /auth-login returns a JWT valid for 8 hours. Send it on every app request. Each sign-in creates a session, listed in GET /account; signing out or revoking the session ends the token at once.

Authorization: Bearer <token>

Integrations: API key

HR2, Finance and ESS each have their own shared key, sent server to server. A key must be at least 32 characters; until it is set, that integration returns 503. Generate one with openssl rand -hex 32, and never put a key in browser code.

X-API-Key: <shared key>
SystemEnvironment variableRoutesNot configured
HR2HR2_API_KEY/integrations/hr2/*HR2_NOT_CONFIGURED
FinanceFINANCE_API_KEY/integrations/finance/*FINANCE_NOT_CONFIGURED
ESSESS_API_KEY/integrations/ess/*ESS_NOT_CONFIGURED

Passkey: confirming sensitive actions

Each user sets their own passkey in Settings. Generating and releasing payslips send it in the request; CSV exports and Payroll Settings changes confirm it first with verify_passkey on POST /account. It is 6 to 64 characters and must differ from the login password. Five wrong entries lock it for 15 minutes.

A wrong passkey on a payslip endpoint still returns 200, with a false flag and a reason: not_set, invalid or locked (with locked_until). Check the flag, not only the status.

15. Integration: HR2 attendance

Receives attendance records.
